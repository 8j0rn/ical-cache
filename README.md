# iCal Sync Service для WordPress и Авито

Сервис для синхронизации iCal файлов из WordPress и предоставления статических ссылок для Авито.

## Установка

1. Клонируйте репозиторий в папку WordPress:
   ```
   /путь/до/wordpress/8j0rn/
   ```

2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

3. Настройте конфигурацию:
   ```bash
   cp .env.example .env
   nano .env  # Отредактируйте настройки
   ```

4. Создайте необходимые директории:
   ```bash
   mkdir -p data/{cache,logs} public/ical
   ```

## Настройка

Отредактируйте файл `.env`:

```bash
# База данных WordPress
DB_HOST=localhost
DB_NAME=wordpress_db
DB_USER=wordpress_user
DB_PASS=ваш_пароль

# Адрес WordPress сайта
WP_URL=https://ваш-домен.рф

# Пароль для админки
ADMIN_PASSWORD=сложный_пароль
```

## Использование

### Веб-интерфейс

- Главная: `https://ваш-домен.рф/8j0rn/` (требует пароль)
- iCal файлы: `https://ваш-домен.рф/8j0rn/ical/123.ics` (публичный доступ)
- Админка: `https://ваш-домен.рф/8j0rn/admin` (требует пароль)
- Синхронизация: `https://ваш-домен.рф/8j0rn/sync` (требует пароль)

### Командная строка

```bash
# Синхронизировать все объекты
python sync.py --all

# Синхронизировать один объект
python sync.py --id 123

# Очистить старые файлы
python sync.py --cleanup

# Показать статистику
python sync.py --stats
```

### Автоматическая синхронизация (Cron)

Добавьте в crontab:
```bash
# Синхронизация каждые 2 часа
0 */2 * * * /путь/до/python /путь/до/8j0rn/sync.py --all >> /путь/до/8j0rn/data/logs/cron.log 2>&1

# Очистка каждый день в 3:00
0 3 * * * /путь/до/python /путь/до/8j0rn/sync.py --cleanup >> /путь/до/8j0rn/data/logs/cleanup.log 2>&1
```

## Структура проекта

```
8j0rn/
├── .env              # Конфигурация (не в git)
├── app.py           # Основное приложение
├── sync.py          # Скрипт синхронизации
├── data/           # Данные (не в git)
│   ├── cache/      # Кэшированные .ics файлы
│   └── logs/       # Логи приложения
└── public/         # Публичные файлы
    └── ical/       # iCal файлы для Авито
```

## Безопасность

- Админка защищена HTTP Basic Auth
- Пароли хранятся в `.env` файле (не в git)
- Публичные пути (`/ical/`) доступны без пароля
- Логи хранятся отдельно и ротируются

## Решение проблем

1. **Файлы не создаются** - проверьте права на папки `data/cache/`
2. **Ошибка подключения к БД** - проверьте настройки в `.env`
3. **Ошибка загрузки iCal** - проверьте доступность WordPress сайта
